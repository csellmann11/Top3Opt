# Adaptive regularization validation — 2026-09-29

## Decision

Keep the conservative diamond flux, with rank-aware vertex reconstruction.
The variable-beta Taylor method from the supplied text was initially implemented
as a comparison and now lives in `src/taylor_operator.jl`, selectable with
`--flux_scheme taylor`; it also runs successfully, but its product
rule does not give an exactly conservative discrete flux on the graded mesh.
Diamond retains harmonic transmission across the discontinuous cellwise beta.
It was faster and smaller on the reproduced MBB failure mesh; the timing order
reverses on a mesh with many coarse/fine interfaces, as quantified below.

The production substep count follows the original rule, independently of the
operator coefficients. It remains eight for beta0=1 and eta0=15. The old Laplace
rescaling remains disabled in cluster jobs. No PETSc or cluster configuration
changes are required for this fix.

## Reproduced failure

The MBB symmetry case starts with 6,144 hex cells and uses the production error
estimator, marking, mesh adaptation, assembly, and density transfer. A sparse
direct elasticity solve replaces PETSc in the local integration harness.

At iteration 11, after adaptation to 5,290 cells, the old reconstruction produced
an operator infinity norm of **2.1760005714e14**. One four-sample vertex stencil
had singular values approximately

```
2.06990, 1.05409, 1.02414, 1.84250e-15
```

The sample centres are coplanar geometrically. Default `pinv` retained the last
singular direction, which was integration roundoff, giving a nodal weight
1-norm of **1.088e14**. This explains the enormous substep count generated by the
removed operator-dependent rule.

With the dimensionless `sqrt(eps(Float64))` relative rank cutoff, this stencil
has weights approximately `[0.15, 0.15, 0.35, 0.35]`. On the **same saved mesh**,
the assembled operator norm is **100.3946011**. This corrects the geometric
reconstruction rather than clipping flux coefficients or increasing substeps.

## Integration and regression results

- Corrected diamond with the original multiplier implementation: 40 adaptive
  MBB iterations passed. This isolates the reconstruction fix.
- Corrected diamond with the new complete-force volume projection: **120
  adaptive MBB iterations passed**, always using eight substeps. Every iteration
  checks finite densities, density bounds, and target mean density within 1e-8.
  The mesh finished with 3,484 cells. Maximum operator row bound was about 105.36.
- The supplied Taylor product-rule reference: 40 adaptive MBB iterations passed.
- Near-coplanar reconstruction, two-material flux continuity, face orientation,
  constants, conservation, zero beta, uniform/adaptive hex geometry, and nodal
  affine reconstruction pass the focused tests.
- Five deliberately unbalanced hex meshes with **direct size ratios 2:1 through
  32:1** preserve constants and conservation. All eigenvalues of the tested
  diffusion-only Euler maps `I + R/(8*15)` have modulus at most one to roundoff.
  Row norms can exceed 120 on these meshes; row norm alone is too pessimistic
  as a substep selection rule.
- The complete-force volume projection passes 138 assertions against an
  independent bisection reference, including unequal volumes, clipping, and
  large force offsets. It took at most 13 iterations in these tests.
- The Taylor comparator passes manufactured smooth variable-beta and quadratic
  density checks, constant preservation, and constant-beta agreement with the
  existing unrescaled Taylor Laplacian.
- Extruded Voronoi geometry passes finite-coefficient, constant-preservation,
  and conservation checks. In total, the three focused test scripts pass **391
  assertions**, in addition to the integration checks above.

## Local performance on the iteration-11 mesh

Julia 1.12.6 on Windows; BLAS threads set to one. Assembly timings are the best
of five warmed calls and include mesh neighbourhood/reconstruction work. They
exclude elasticity solves and Julia compilation. Allocation totals are traffic
per assembly call, not peak memory or cluster job memory requirements.

| Method | Assembly | Stored matrix | Allocations | Nonzeros | `norm(volumes' * R, Inf)` |
|---|---:|---:|---:|---:|---:|
| Corrected diamond | 35.6 ms | 0.63 MiB | 25.5 MiB | 38,691 | 1.14e-16 |
| TPFA | 20.0 ms | 0.58 MiB | 19.1 MiB | 35,250 | 8.15e-17 |
| Taylor product rule | 62.9 ms | 1.41 MiB | 59.1 MiB | 89,988 | 0.2554 |

TPFA is included as a baseline but omits the correction needed on nonorthogonal
coarse/fine interfaces. The Taylor comparator contracts each ridge solve to the
three gradient rows and Laplacian and assembles one sparse operator; it does
not construct separate global derivative matrices.

In the 120-step final integration run, the median complete density-update time
after the first iteration was **6.86 ms**. This includes strain-energy evaluation,
eight explicit substeps, and volume projection. Hardware and other system load
affect these measurements; they are not cluster performance guarantees.

On the separate deterministic graded fixture (3,376 cells, many nonorthogonal
interfaces), diamond assembly took **65.9 ms** and stored **1.02 MiB**, versus
**23.5 ms** and **0.95 MiB** for Taylor. Conservation residuals were respectively
`3.76e-16` and `0.1006`. Diamond is therefore chosen for its conservative treatment
of variable beta and the successful robustness checks, not because it is faster
on every mesh. Both methods assemble once per mesh state and then use sparse
matrix-vector products during density updates.

## Reproduce

Run from the repository root with its existing Ju3VEM dependency:

```sh
julia --project=. --startup-file=no Tests/diamond_flux.jl
julia --project=. --startup-file=no Tests/density_projection.jl
julia --project=. --startup-file=no Tests/taylor_reference_tests.jl
julia --project=. --startup-file=no Tests/regularization_benchmark.jl diamond 120 3
julia --project=. --startup-file=no Tests/regularization_benchmark.jl taylor 40 3
julia --project=. --startup-file=no Tests/regularization_comparison.jl
```

The last command compares a deterministic graded mesh. It optionally accepts a
serialized `(cv, states, pars)` snapshot. The benchmark saves such a snapshot to
`Results/bad_diamond_stencil.bin` when diamond coefficients exceed its diagnostic
threshold. The original failure snapshot and local logs are retained in ignored
`Results/`; they are not required by the regression suite.

## Limits

The corrected diamond operator is not guaranteed symmetric or monotone. The
fixed-step stability checks cover the specified hex fixtures and are not a proof
for arbitrarily distorted or highly anisotropic polyhedra. Dropping unresolved
directions prevents fitting numerical noise; a coplanar sample set cannot
determine an arbitrary three-dimensional affine field. Constants and paired
face-flux conservation are still preserved.

The integration benchmark validates the density/adaptivity path with a direct
elasticity solver. It does not validate the cluster PETSc runtime, shared cache,
or Slurm resource settings. A short cluster rerun remains appropriate.
